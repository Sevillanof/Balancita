# Capturing public Kraken Futures market data

The isolated FK-02 capture utility stores public `PF_XBTUSD` observations in a new SQLite database and exports their normalized event stream as JSONL. It does not connect to application startup, submit orders, use credentials, or access the spot market store.

## Quick path

Use a newly created temporary directory and an explicit capture mode. `mock` is offline fixture data; `paper_live` requests the current public catalog and opens the documented public market-data WebSocket for at most 30 seconds.

```bash
CAPTURE_DIR="$(mktemp -d -t balancita-futures-market)"
DB="$CAPTURE_DIR/balancita-futures-market-capture.sqlite"
EXPORT="$CAPTURE_DIR/balancita-futures-market-events.jsonl"

# Deterministic offline fixture; stdout is JSONL and diagnostics go to stderr.
node --experimental-strip-types server/src/features/kraken-futures/capture-market.ts \
  --mode mock --db-path "$DB" --export "$EXPORT"

# Optional public-only capture (1–30 seconds), using another new directory.
LIVE_DIR="$(mktemp -d -t balancita-futures-market)"
node --experimental-strip-types server/src/features/kraken-futures/capture-market.ts \
  --mode paper_live --db-path "$LIVE_DIR/balancita-futures-market-capture.sqlite" \
  --seconds 15 --export "$LIVE_DIR/balancita-futures-market-events.jsonl" > /dev/null
```

The utility refuses a database/export path outside the OS temporary directory, any existing file, a missing mode, or an unknown mode. `paper_live` is a market-data mode only; it does not enable execution.

## Data and safety boundaries

| Area               | Contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Instrument         | Internal ID `kraken-futures:PF_XBTUSD`; public catalog must confirm the expected linear BTC/USD contract before it is marked eligible. EEA minimum size/tick are versioned rules, not fields inferred from the catalog.                                                                                                                                                                                                                                                                                                                                                                                  |
| Decimal fidelity   | Provider JSON numeric tokens are converted from their original token text to decimal strings before any IEEE-754 conversion. Sequence numbers and UTC millisecond timestamps must be safe integers.                                                                                                                                                                                                                                                                                                                                                                                                      |
| Book recovery      | The collector accepts a new snapshot before deltas. Kraken's book example advances from sequence `326072249` to `326094134` (a difference of 21,885), so numeric jumps cannot safely be interpreted as missing messages. The collector requires strictly increasing sequence values; jumps are counted and tagged `monotonic_only_unproven`, not called gaps. A repeated/regressing value, crossed book, reconnect, or persistence error invalidates depth and requests a fresh snapshot. Depth is explicitly **not executable-eligible** until provider sequence continuity is documented and verified. |
| Freshness          | Initial book/ticker stale limit is 3 seconds. Heartbeats do not refresh market timestamps. No-trade intervals do not themselves mean the feed is stale.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Trades and candles | Trade UIDs deduplicate across connection epochs. Snapshot trades are retained as recovered evidence and do not create eligible live candle inputs. Candles are event-time buckets with received-time availability, exact BTC volume strings, append-only revisions, and explicit observed-trades-only coverage. No empty/zero-volume candles are invented.                                                                                                                                                                                                                                               |
| Funding            | An absent funding field is unknown. An explicit zero is observed zero. Relative/predicted rates and ambiguous funding-time fields are not converted to realized USD/hour here.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Receipt chronology | SQLite insertion `rowid` is exposed as `receivedSequence` on replay/export and is the stable global receipt-order tiebreak; provider `seq` remains feed-local and is never compared across trade/book/ticker. `receivedSequence` is export/replay metadata, excluded from normalized persisted event content and its hash. A duplicate event allocates no new receipt sequence.                                                                                                                                                                                                                          |
| Durability         | Market evidence, catalog versions, gap records, snapshots, and candle revisions are guarded against SQL UPDATE/DELETE by market-only triggers installed in additive schema version 2. Legacy tables and migrations are untouched.                                                                                                                                                                                                                                                                                                                                                                        |
| Costs and terms    | This capture stage does not price account-specific fees or claim exchange execution parity. Kraken states that certain non-personal commercial uses of public API data require prior permission; use this tool only within applicable personal/non-commercial terms and do not redistribute captured data without confirming permission.                                                                                                                                                                                                                                                                 |

Catalog mismatch results in `metadata_invalid`; no silent fallback to an assumed instrument. Persisted raw frames, normalized events, snapshots, gaps, candle revisions, and metadata are isolated under `paper_futures_market_*` tables. Keep the file as research evidence; do not point this command at the application database.

## Provider evidence checked on 2026-10-02

- [Trade feed](https://docs.kraken.com/api/docs/futures-api/websocket/trade/) documents `trade` and `trade_snapshot`, UID, side/type, sequence, millisecond time, quantity, and price.
- [Book feed](https://docs.kraken.com/api/docs/futures-api/websocket/book/) documents `book_snapshot`, deltas, sequence, timestamps, and zero-quantity level removal.
- [Ticker feed](https://docs.kraken.com/api/docs/futures-api/websocket/ticker/) documents the distinct last/bid/ask/mark/index values, one-second throttling, and current versus predicted and relative funding fields. It says zero-valued funding fields may be omitted.
- [Instrument catalog](https://docs.kraken.com/api/docs/futures-api/trading/get-instruments/) is public at `https://futures.kraken.com/derivatives/api/v3/instruments`. The live GET on 2026-10-02T18:35:49.777864Z reported `PF_XBTUSD` as `flexible_futures`, `BTC:USD`, `contractSize=1`, quantity precision 4, `tickSize=1`, tradeable and not expired. The API schema does not supply the EEA minimum lot.
- [EEA linear specifications](https://support.kraken.com/ca/articles/perpetual-contract-specifications-for-clients-in-the-eea), updated 2026-09-30, list `PF_XBTUSD` minimum lot `0.0001 BTC` and tick `1 USD`, plus hourly funding periods and continuous accrual semantics. These constraints are versioned locally and must be checked again before any live paper entry eligibility is enabled.
- [EEA derivatives fees](https://support.kraken.com/articles/fees-for-derivatives-trading-eea), updated 2026-03-17, list base maker/taker rates 0.0200% / 0.0500%; these are a lab baseline, not an account-tier lookup. The catalog reference marks the old futures fee-schedule fields deprecated effective 2026-06-22.
- [Futures API introduction and terms](https://docs.kraken.com/api/docs/guides/global-intro/) separates spot/futures APIs and says certain non-personal commercial public-data uses require prior permission. [Derivatives REST request limits](https://support.kraken.com/articles/360022635612-request-limits-rest-api-derivatives) says public endpoints have no cost; spot limits are not imported here.

This evidence validates public schemas and current product metadata only. Kraken does not document the book sequence as contiguous in the cited contract; a live collector must therefore not claim proof that every update was received. `live` describes fresh feed delivery, not executable-book completeness. No execution quality, account availability, or profitability is guaranteed. Native review and full product acceptance remain separate gates.

This bounded capture proves public feed delivery only, not complete book fidelity.
